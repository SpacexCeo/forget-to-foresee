Try to cheat Forget to Foresee

Six attacks a player could try, the guard that refuses each one, the error you get back and the test that proves it. NEAR testnet only; nothing here has real-world value. Source: github.com/SpacexCeo/forget-to-foresee.

No rejected transaction is linked yet: we have not attempted these attacks live on testnet. Each card ends with a command the owner can run to produce one. No keys are in the repository.

1. Replay a signed request refused twice

Attack
Send the same signed town move (pledge, claim, gate payment) again, so it runs twice.
Guard
The relayer keeps used request hashes and also asks the chain (act_request_used, gate_request_used); the contract stores each hash once and panics on a second use, even if the relayer were bypassed.
Error
Relayer 409 {"error":"replayed"} (relayer/lib/town-act.js, relayer/lib/town-gate.js). Contract ERR_ACT_REQUEST / ERR_GATE_REQUEST: "this signed request was already used" (contracts/town/src/lib.rs).
Test
relayer/tests/town-gate.test.mjs: "a signed request credits, then pays the gate for the guest once; replays and second payments are refused"; relayer/tests/p2p.test.mjs: "signed requests only, each used once".
Owner can run
POST /api/town/act twice with the same body from a test guest; the second answer is 409.

2. Claim a chest twice, or roll again bounded

Attack
Repeat an opening request, or open chests until a good roll comes.
Guard
A chest is never rolled: each opening takes the next position of a 10,000-card deck whose root and seed are fixed on chain before the first opening, so repeating cannot pick a card. A repeated batch request_id never re-sends. The contract allows 30 openings per account per day, and the request must be fresh and signed by a key on the account.
Error
429 daily_cap / contract ERR_DAILY; stale, bad_signature, 403 for a key not on the account (relayer/lib/chest.js, contracts/loot-chest/src/lib.rs).
Test
relayer/tests/chest-batch.test.mjs: "a repeated request never re-sends"; relayer/tests/chest.test.mjs: "a full season visits every position once"; node tools/verify-chest/verify.mjs re-checks every opening.
Owner can run
31 openings for one test guest in a day; the 31st transaction fails with ERR_DAILY.

3. Forge a quest receipt refused

Attack
Claim the boss dragon, or silk, with a made-up expedition log ("I killed the boss").
Guard
The expedition log is a signed, hash-chained list that the relayer stores; a fork or a gap is refused, and each entry is checked against the rules (tier, silk, a quest done twice, kills too fast or too many, times in the future). The boss dragon is minted only if the stored, verified log has the boss down.
Error
fork, gap, log_invalid, implausible (relayer/lib/expedition-store.js); 409 boss_not_down (relayer/lib/companion.js).
Test
relayer/tests/expedition-store.test.mjs: "a fork or a gap is refused" and "T2 kills, forged silk, a quest twice, kills too fast or too many, the future are refused"; relayer/tests/companion.test.mjs: "boss needs the boss down in the stored log".
Owner can run
POST /api/companion/claim with reason: "boss" from a fresh test guest; the answer is 409 boss_not_down.

4. Take the free mint twice refused

Attack
Ask for a second guest account and Elise with the same key, or start two at once.
Guard
The guests contract keeps one guest per public key and a pending marker while one is created; 200 new guests a day for everyone.
Error
ERR_EXISTS: "this key already has a guest with Elise"; ERR_PENDING; relayer 429 daily_cap (contracts/guests/src/lib.rs, relayer/lib/core.js). The relayer answers a repeat idempotently with the existing guest.
Test
contracts/guests unit tests one_guest_per_key, a_key_in_flight_cannot_start_twice; relayer/tests/core.test.mjs: "idempotent; honest failures; cap".
Owner can run
Call create_guest on guests.ftf-coordinator.testnet with an already-used key; it fails with ERR_EXISTS. A new key per browser is the known limit.

5. Buy above (or below) the price band refused

Attack
List or buy an item far from its fair price, to move silk between your own accounts.
Guard
The player market's shared rules (game and relayer) reject any unit price outside the item's band.
Error
outside_band with the band's min and max (relayer/lib/market-rules.js).
Test
relayer/tests/p2p.test.mjs: "2 % fee rounded up, the band, minimum total, limits, self trade, the daily cap".
Owner can run
Not on chain yet: the player market settles on chain only after town v5 / items v2 are deployed.

6. Trade with yourself refused

Attack
Buy your own listing to fake volume or a price.
Guard
The buyer may not be the listing's seller.
Error
409 self_trade (relayer/lib/market-rules.js, relayer/lib/p2p.js).
Test
relayer/tests/p2p.test.mjs (same test as above).
Owner can run
Same as 5: on chain after the v5 / v2 deploy.
